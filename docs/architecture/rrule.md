# Решение о миграции расписания на RRULE

HTTP-адаптеры v1 и v2 используют общий `MassService`. `DeprecatedMassService` адаптирует параметры и результаты для v1. В эксплуатации сначала работает v1, затем клиент и API переключаются на v2.

В Mongo расписание хранится в `calendar`. `dtstart` и элементы `exdates` — BSON-даты, `rrule` — строка iCalendar без префикса. Перед раскаткой существующие записи нужно перенести и проверить. Рабочие пути исходят из наличия валидного календаря у каждой мессы.

## API v1

V1 принимает разовые и еженедельные расписания. Для еженедельной мессы `startDate` обязателен и должен приходиться на один из выбранных дней. Маппер переводит даты, время и дни недели из Europe/Minsk в UTC и восстанавливает поля v1 при чтении, сохраняя порядок дней. Начало разовой мессы задаёт `singleStartTimestamp`. Для неё сохраняется правило `FREQ=DAILY` с `UNTIL`, равным `DTSTART`.

Удаление интервала оставляет события до и после него. При разбиении исходная серия сохраняет ID, её `UNTIL` приходится на последнюю секунду перед интервалом, а продолжение получает новый ID и `DTSTART` первого оставшегося вхождения.

## API v2

- `POST /api/v2/masses` создаёт серию и возвращает `201` с её данными. `GET /api/v2/masses/{id}` возвращает активную серию. `DELETE /api/v2/masses/{id}` помечает серию удалённой.
- `DELETE /api/v2/masses/{id}/occurrences/{start}` добавляет момент начала в `EXDATE`. Повторная отмена оставляет одну запись. Клиент передаёт даты в UTC, API возвращает их в UTC.
- Синтаксис и вычисление вхождений обрабатывает iCal4j. Доменная валидация проверяет, что `DTSTART` входит в правило.

## Пересечения и выдача

Пересечение — совпадение начала хотя бы одного фактического вхождения двух активных месс одного прихода. Поиск учитывает `EXDATE`. Для пары с заданным `UNTIL` проверяется общий период действия до самой ранней конечной границы включительно. Если `UNTIL` отсутствует у обеих серий, проверяется окно от начала сегодняшнего дня по UTC до начала того же дня через календарный год. При конфликте API возвращает HTTP `400`, код `MASS.011` и данные конфликтующей мессы в `errors[].payload.duplicateMass`.

Недельный календарь и поисковый индекс вычисляют вхождения из сохранённого расписания. Индексатор получает вхождения напрямую и записывает время в существующем формате Meilisearch для Europe/Minsk.

Gradle проверяет архитектурные зависимости. HTTP и индексацию проверяем с тестовыми MongoDB и Meilisearch через Testcontainers, вычисления расписания — отдельно.
